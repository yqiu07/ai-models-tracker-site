### 节点 1-3：平台模型目录采集（auto_collect.py）

**本质**：不是 LLM 调用，而是调用各平台的**模型目录 API**（`/models` 端点），获取模型列表。

#### 当前实际查询了哪些平台？

**答：只查了 DashScope 百炼（阿里）**。原因：`.env` 中只配置了 `LLM_API_KEY` + `LLM_API_BASE`（指向 DashScope），其他 11 个平台都没有配置 API Key，因此全部被跳过。

```
PLATFORM_REGISTRY 注册了 12 个平台：
  ✅ DashScope 百炼 → LLM_API_KEY + LLM_API_BASE → 已配置，实际查询
  ❌ 硅基流动 SiliconFlow → SILICONFLOW_API_KEY → 未配置，跳过
  ❌ DeepSeek → DEEPSEEK_API_KEY → 未配置，跳过
  ❌ 火山引擎 → VOLCENGINE_API_KEY → 未配置，跳过
  ❌ Moonshot → MOONSHOT_API_KEY → 未配置，跳过
  ❌ 智谱 → ZHIPU_API_KEY → 未配置，跳过
  ❌ 百度千帆 → QIANFAN_API_KEY → 未配置，跳过
  ❌ MiniMax → MINIMAX_API_KEY → 未配置，跳过
  ❌ 腾讯混元 → HUNYUAN_API_KEY → 未配置，跳过
  ❌ 阶跃星辰 → STEPFUN_API_KEY → 未配置，跳过
  ❌ OpenRouter → OPENROUTER_API_KEY → 未配置，跳过
  ❌ 酷爱 Kuai → KUAI_API_KEY → 虽有Key但 KUAI_API_BASE 不等于 api_base_env 配的值
```

#### 查询逻辑（代码路径：`auto_collect.py` 第 1200-1320 行）

```
collect_platform_catalogs(since_int, until_int)
  → 遍历 PLATFORM_REGISTRY
  → 检查 os.environ.get(api_base_env) 和 os.environ.get(api_key_env)
  → 有 Key 的平台调用 _collect_single_platform(config)
    → 根据 type="openai" 调用 _fetch_openai_compatible_models(config)
      → GET {api_base}/models  (Header: Authorization: Bearer {api_key})
      → 返回 [{id, created}, ...]
    → 遍历每个模型:
      → 跳过 skip_patterns 匹配的（如 qwen-1.8b）
      → 时效性过滤: if created_ts < cutoff_ts(2026-01-01): 跳过
      → 调用 _model_to_row() 转换为标准行
        → 官网 = config["doc_url"]（⚠️ 写的是平台文档URL，不是模型官网）
        → 备注 = config["note"]（⚠️ 写的是平台名称，毫无意义）
        → 发布时间 = datetime.fromtimestamp(created_ts)（⚠️ 这是平台上架时间，不是模型发布时间）
```

#### ⚠️ 已知问题

| 问题 | 说明 | 影响 |
|------|------|------|
| **时间过滤阈值过低** | `cutoff_ts = 1735689600`（2026-01-01），用户要求 ≥ 2026-03-19 | 大量旧模型混入增量 |
| **发布时间 ≠ 模型发布时间** | `created_ts` 是平台上架时间（如 DashScope 的模型创建时间戳），不是模型提供方的实际发布日期 | DeepSeek V4 显示 05-09（上架日），实际 04-24 发布 |
| **官网字段错误** | 填的是 `config["doc_url"]`（如 DashScope 文档链接），不是模型自身官网 | 所有平台采集的模型官网都错 |
| **备注毫无意义** | 填的是 `config["note"]`（如"DashScope 百炼平台"），没有任何模型特征信息 | 不如留空 |
| **无 web search 校验** | 采集后没有调用任何 LLM 做发布时间/官网/备注的校验和补全 | 数据质量低 |
| **只查了 1/12 个平台** | 其他 11 个平台没有配置 API Key | 覆盖率受限于配置 |

### 节点 4：LLM 提取腾讯研究院模型（Extract/extract_models_llm.py）

**调用时机**：步骤 2.5（从腾讯研究院文章全文中提取新发布模型信息）

#### API 配置

| 参数 | 主 API（优先） | 备选 API（Fallback） |
|------|---------------|---------------------|
| **提供商** | kuai（代理平台） | DashScope 百炼（阿里云） |
| **模型** | `claude-opus-4-6` | `qwen-plus`（或 `LLM_MODEL` 环境变量） |
| **环境变量** | `KUAI_API_KEY` + `KUAI_API_BASE` | `LLM_API_KEY` + `LLM_API_BASE` |
| **当前值** | `sk-8eiv...2A` + `https://api.kuai.host/v1` | `sk-5ed8...1230` + `https://dashscope.aliyuncs.com/...` |
| **Endpoint** | `POST {api_base}/chat/completions` | 同上 |
| **温度** | `0.1` | `0.1` |
| **max_tokens** | `4000` | `4000` |
| **超时** | `300` 秒 | `300` 秒 |

#### Prompt 核心内容（完整 Prompt 见脚本第 41-120 行）

**角色**：AI 模型追踪分析师
**任务**：从腾讯研究院文章中提取新发布/新版本/新上线的 AI 模型
**核心约束**：
- 只提取"新发布"，不提取"被提及"
- 排除产品泛称（ChatGPT、Cursor 等无版本号的）
- "被报道" ≠ "当天发布"——必须从正文中找发布时间锚点
- 不确定发布日期则留空，禁止用文章日期填充

**提取字段**（12 个）：
`model_name`, `company`, `domestic`, `open_source`, `size`, `model_type`, `can_reason`, `task_type`, `release_date`, `release_date_source`, `website`, `brief`

**输出格式**：JSON 数组

#### 调用流程

```
call_llm(article_text, api_key, api_base, model, article_date)
  → 主 API: _call_llm_once(article_text, kuai_key, kuai_base, "claude-opus-4-6")
    → POST {kuai_base}/chat/completions
    → 成功 → 返回结果
  → 主 API 失败:
    → Fallback: _call_llm_once(article_text, llm_key, llm_base, "qwen-plus")
```

#### ⚠️ 已知问题

| 问题 | 说明 |
|------|------|
| Prompt 质量好 | 时效性校验机制完善（三重校验），有明确的排除清单和示例 |
| 文章截断 | `article_text[:8000]` 硬截断，长文章可能丢失后半部分的模型信息 |
| 无批量并发 | 逐篇串行调用，多篇文章时效率低 |

### 节点 5：GPT-5.5 审核（review_models.py）

**调用时机**：步骤 3（对新增模型进行名称规范性审核 + 字段补全 + 重要性评级）

#### API 配置

| 参数 | 值 |
|------|-----|
| **提供商** | kuai（代理平台） |
| **模型** | `gpt-5.5`（由 `REVIEW_MODEL` 环境变量控制） |
| **环境变量** | `KUAI_API_KEY` + `KUAI_API_BASE` |
| **当前值** | `sk-8eiv...2A` + `https://api.kuai.host/v1` |
| **Endpoint** | `POST {api_base}/chat/completions` |
| **温度** | `0.1` |
| **max_tokens** | `8000` |
| **超时** | `180` 秒 |
| **批次大小** | 每批 20 个模型（`REVIEW_BATCH_SIZE`） |
| **批次间隔** | 2 秒（`REVIEW_BATCH_DELAY`） |

#### Prompt 核心内容（完整 Prompt 见脚本第 24-130 行）

**角色**：资深 AI 模型追踪分析师
**四项任务**：
1. **名称规范性审核**：检查模型名是否为产品泛称（无版本号），标记 `should_remove`
2. **旧模型检测**：2024 年或更早发布的模型
3. **字段补全**：尺寸/发布时间/官网/任务类型（仅填高置信度的）
4. **重要性评级**：高/中/低 + 理由（基于重点关注公司清单）

**输出格式**：JSON 数组，每个元素含 `model_name`, `should_remove`, `corrections`, `confidence`, `importance`, `importance_reason`, `issues`, `notes`

**应用逻辑**：
- 高置信度修正 → 自动应用到 DataFrame
- 低置信度修正 → 写入"核实情况"列，待人工确认
- `should_remove=true` + 高置信度 → 直接删除行
- 重要性评级 → 追加到备注末尾（如 `[重要性:高|OpenAI旗舰模型]`）

#### ⚠️ 已知问题

| 问题 | 说明 |
|------|------|
| **不补全官网和备注** | Prompt 里让 GPT-5.5 补全"官网"字段，但实际上 GPT-5.5 没有 web search 能力，只能基于训练数据猜测 |
| **备注不是语义化生成** | 审核 Prompt 中没有要求生成语义化备注（如"MoE架构；1T参数"），只做了重要性评级追加 |
| **无 web search 验证发布时间** | GPT-5.5 补全的发布时间可能不准，需要 web search 交叉验证但代码中没有 |

## 四、DeepSeek V4 变体澄清

根据 Web Search 验证：

| 名称 | 来源 | 真实发布日期 | 说明 |
|------|------|-------------|------|
| `DeepSeek-V4-Pro` | DeepSeek 官方 | **2026-04-24** | 官方名称，预览版 |
| `DeepSeek-V4-Flash` | DeepSeek 官方 | **2026-04-24** | 官方名称，预览版 |
| `DeepSeek-V4-Pro-Max` | DashScope 别名 | DashScope 上架: 2026-05-09 | DashScope 平台上的别名/增强版 |
| `DeepSeek-V4-Flash-Max` | DashScope 别名 | DashScope 上架: 2026-05-09 | DashScope 平台上的别名/增强版 |
| `deepseek-v4-pro` | 采集到的 | 记录为: 2026-05-09 ❌ | **错误**：用的是 DashScope created 时间戳，不是模型发布时间 |
| `deepseek-v4-flash` | 采集到的 | 记录为: 2026-05-09 ❌ | **错误**：同上 |

**结论**：
- 采集到的 `deepseek-v4-flash` / `deepseek-v4-pro` 就是 DeepSeek V4 预览版（4月24日发布），但 DashScope 上架时间是 5月9日
- 图片中的 `DeepSeek-V4-Flash-Max` / `DeepSeek-V4-Pro-Max` 是 DashScope 平台的增强别名，可能是同一模型的不同配额/配置版本
- **发布时间应该标注为 2026-04-24**（模型提供方发布日期），而不是 2026-05-09（平台上架日期）
